grofe, the agent-native tmux

A free terminal multiplexer in Rust. It speaks tmux, tells you which coding agent is waiting on you, and brings your work back after a reboot.

Why grofe exists

It keeps what tmux got right: sessions, windows and panes, a server that outlives your terminal, a prefix key, split-window and send-keys. It changes the parts people keep fighting.

Where it hurtsIn tmuxIn grofe
Coding agents

Every agent is one pane among many, and you go looking for the one that stopped.

It tracks each agent's state, counts the ones that need you, notifies you and jumps there.

Reboots

Sessions die with the machine unless tmux-resurrect and tmux-continuum save and restore them.

Panes come back in their layout and folders, and your editor and agents come back running. grofe reboot-check says what will return.

Config

tmux.conf has no schema, and nothing tells you which file set a value.

TOML with a schema. A typo names the file, the line and the setting you meant, and show-config --explain names the file that set a value.

Status line

#() segments fork a shell as the status line redraws.

They run on a timer, one at a time, and the output is cached. A redraw never forks.

Scripting

Shell scripts, through run-shell and if-shell.

Luau inside the server: keys, events, timers and status widgets, each call held to 50 ms and 64 MiB.

Plugins

TPM clones plugins, with no lockfile to keep machines in step.

grofe pack pins every plugin to a commit in a lockfile, Luau plugins and tmux plugins alike.

Panes

Panes share one-cell borders, and a pane's number is something you look up.

Framed tiles with a title and zoom, float and close controls. Drag one to swap, dock or float it.

Luau inside the server

In the spirit of Neovim: an init.luau next to your config runs at start and on every reload. It binds keys, reacts to events, runs timers and feeds the status line.

50 msof run time for every call into Lua

64 MiBof memory, in a sandbox with no io

Go over and grofe aborts the call, logs it and carries on, so a script can never freeze the server. Slow work runs in grofe.system, outside the server, and calls you back.

( 1 ) nvim · init.luau( z f x )
local function refresh()
  grofe.system({ "git", "rev-parse", "--abbrev-ref", "HEAD" }, function(r)
    local branch = r.code == 0 and r.stdout:gsub("%s+$", "") or ""
    grofe.cmd({ "set-option", "-g", "@git", branch })
  end)
end

refresh()
grofe.every(2000, refresh)

Know the gaps first

  • TPM itself does not run: grofe pack replaces it. You do not need resurrect or continuum; grofe restores sessions itself.
  • Control mode (-C, -CC) has a first slice: attach and new-session.
  • grofe does not run on Windows.
  • Keep real tmux installed while you try it. Switching from tmux

Before you switch

Can I use it for real work today?

grofe is an early preview. It is in daily use by its author and passes a large tmux compatibility suite, but expect rough edges and keep real tmux installed while you try it. Bug reports are very welcome.

Does it read my tmux.conf?

No. Your setup moves over once: grofe import-tmux converts options, key bindings, hooks and status formats to TOML and never touches the original.

Will my tmux plugins work?

Yes, through grofe pack, which replaces TPM. Declare each plugin as [[pack]] in config.toml; a repo with *.tmux files and no grofe manifest loads as a tmux plugin, pinned to a commit in pack-lock.toml, so the same plugins run on every machine. They load after grofe pack sync clones them, then grofe reload. Resurrect and continuum are not needed: grofe restores your sessions itself.

Which systems and terminals?

macOS and Linux. It is built and tested against Ghostty and WezTerm; WezTerm needs config.enable_kitty_keyboard = true. Other terminals get the older key encoding and skip what they lack.

Can I work on another machine?

Yes. grofe -r host attaches to a session there over ssh and installs grofe on it if you say yes. A dropped link or a laptop asleep shows a reconnect bar and comes back with nothing lost; URLs, dropped files, ports and the ssh agent are forwarded; keys echo locally on slow links. Save machines with grofe machine add and switch between them, and their agents, in one window. See Remote sessions.

Is it trying to be Zellij?

No modal interface and no WebAssembly plugins: just tmux's way of working, with the rough edges taken off.

Why Rust?

Not for speed; tmux is already fast. A single binary with no runtime dependencies, the terminal emulator inside Alacritty, and memory safety for a long-running process that holds your live work. The attached client is thin, so if it crashes your panes don't notice.

Install grofe

Homebrew, on macOS and Linux

$ brew install termage/tap/grofe

Or with cargo

With Rust 1.88 or newer from rustup. It lands in ~/.cargo/bin.

$ cargo install --locked grofe

Or a package from the release

Each release carries a .deb and an .rpm for Debian, Ubuntu and Fedora, and binaries for macOS and static ones for Linux, x86_64 and arm64. Every file is listed in SHA256SUMS and has a build attestation, so gh attestation verify <file> --repo termage/grofe proves it was built here.
