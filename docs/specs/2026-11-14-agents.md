# Agents: status, picker, sidebar, grid, notifications, key menu

**Date:** 2026-11-14
**Status:** draft, owner-approved direction (discussion 2026-11-14), revised
after a spec review the same day (4 blockers, 12 should-fix, all taken).
**Reverses:** D10 and the M7 drop (owner ruling 2026-10-06). Agent awareness
moves into grofe; the session manager is adjusted to it (§11).
**Inspiration:** herdr (states, done-until-seen, toast delivery), Rex's
Program Status Protocol (OSC 7501), cmux (attention ring, notification panel,
jump to latest), tmux-claude-session-manager (the picker rows and keys),
opensessions (what not to do: an out-of-process sidebar kept in sync by
hooks).

## Goal

Running several coding agents in grofe should be easy to keep track of:

- grofe knows which panes run an agent, and what each one is doing.
- You see at a glance who needs you, jump there in one key, and get told when
  you are looking elsewhere.
- It works for any agent, not only Claude.
- grofe stays a generic multiplexer: agent kinds are config data, and the
  status machinery is driven by reports any program can send.

Every surface is optional and set in the TOML config: a user can have the
picker only, the sidebar only, both, or neither.

## What the owner decided (2026-11-14)

1. Agent handling lives in grofe; the session manager is wired to it. D10/M7 is reversed.
2. opensessions, tmux-claude-session-manager and tmux-which-key leave
   the session manager's plugin layer (§11).
3. Surfaces: status badge, picker, sidebar, grid, notification tray with
   toasts, desktop notifications, a native key menu on `prefix Space`.
4. The picker lists agents only. Its rows and keys follow
   tmux-claude-session-manager's.
5. The grid is preview only.
6. The sidebar is hidden until toggled.
7. The scratchpad keys (`a`, `S`, `A`, branch `feat/scratchpads`) stay.
8. Any agent, not just Claude. grofe ships the integrations.
9. OSC 7501 is read from day one.
10. Desktop notifications on macOS and Linux; each notification can be
    dismissed; notifications can be turned off entirely.
11. Starting agents is in scope, optionally in a new worktree.

## Rulings

- Ruling: no mapping from `@private_agent_state` (because the session manager is changed
  to call `grofe agent report`, §11).
- Ruling: no progress bars; OSC 7501 `progress=` and `title=` are ignored.
- Ruling: fuzzy matching is an in-tree subsequence scorer, no new crate
  (lists are tens of rows).
- Ruling: notifications live in memory only, not across a restart.
- Ruling: the key menu shows key tables only; no `[menu]` table.
- Ruling: grofe does not pick the agent's conversation id at launch; the
  first report carries it.
- Ruling: no screen-pattern matching (cut in review: no shipped kind would
  use it; agents without hooks get attention from the bell, §3.3). Add it
  when an agent with neither hooks nor a bell matters.
- Ruling: nothing about an agent is persisted. A restored pane runs its
  resume command (§2.6), the scan sees the agent again, and its first hook
  report fills in the rest.
- Ruling: no click actions on desktop notifications (cut in review: they need
  a long-lived notifier process per notification and name no client).
- Ruling: the sidebar is right side only (`// ponytail:` a left side needs a
  `window_left` offset at every `window_top` site, 12 sites in 6 files).

## 1. Terms

- **Agent pane:** a pane with an agent record. A pane gets one when its
  foreground program matches a configured kind (§3.1), or when a report
  arrives for it (§3.2).
- **Kind:** a named agent type from `[agents.kinds.<name>]`: how to recognise
  it, how to resume it, how to set it up. Built in: `claude`, `codex`,
  `opencode`, `pi`, `gemini`, `aider`. A report may name an unconfigured
  kind; such a kind has no resume and no desktop notifications (§6.4).
- **Attention:** an agent needs you when it is `blocked` or `error`, or its
  `unseen` flag is set.

## 2. The agent model

### 2.1 State per pane

Agent records live in the server state, keyed by pane id
(`State.agents`), not in the model and not as options.

| Field | Meaning |
|---|---|
| `kind` | kind name, `[A-Za-z0-9._-]{1,32}`; anything else is rejected |
| `state` | `idle`, `working`, `blocked`, `done`, `error` |
| `blocked_kind` | `permission`, `question`, `auth`, or none; only with `blocked` |
| `msg` | one line, sanitised (§2.7), at most 200 chars |
| `since` | when `state` last changed (monotonic, plus wall clock) |
| `unseen` | set on entering `blocked`, `done` or `error` while the pane is not seen, and by §3.3; cleared when seen (§2.4) |
| `session_id` | the agent's conversation id, if reported |
| `reported` | whether any report ever arrived |
| `last_report` | the sender's timestamp of the newest applied report (§2.2) |
| `binding` | the process the record belongs to (§2.3) |

the session manager's old state names map as `completed` to `done`, `exited` to clear.

### 2.2 Transitions

- A report sets `state`, `blocked_kind`, `msg`, and `session_id` when given;
  `since` only when the state changed.
- **Ordering:** each report carries its sender's timestamp (the CLI's start
  time, in microseconds; the scanner's receive time for OSC 7501). A report
  older than `last_report` is dropped. Claude runs tools in parallel, so a
  late `PostToolUse working` must not undo `Stop done`.
- A report equal in state and message to the current one changes nothing: no
  event, no redraw.
- `working` or `idle` clears `unseen`.

### 2.3 Lifetime

The record is bound to the pane's foreground process when it is created
(`resume::Binding::of`: pid plus start time; a stopped process counts as
alive, so `C-z` keeps it). It is removed when:

- the pane closes;
- the bound process is dead (checked by the same sweep `resume.rs` uses,
  §3.1's timing);
- a report says `clear` (OSC 7501) or `exited`.

A report for a pane whose record's process is dead creates a new record bound
to the current foreground process.

### 2.4 Seen

A pane is **seen** when it is the active pane of the current window of an
attached client whose outer terminal is focused. Focus unknown
(`focus-events off`, or no focus report yet) counts as focused. Zoomed and
floating panes count like any pane. Seeing a pane clears `unseen` and marks
its notifications read (§6.2). The check runs in `events::track_focus`, after
every actor message.

### 2.5 Rollups

Urgency, most urgent first: `blocked`, `error`, unseen (any state),
`working`, `idle`, `done`. A window's agent state is its most urgent pane's;
a session's its most urgent window's. Rollups and counts are computed on
read.

### 2.6 Resume

When a report changes `session_id` and the kind has a `resume` template,
grofe sets the pane's resume (the `pane-set-resume` path) to the template
with `{id}` replaced. The id must match `[A-Za-z0-9._:-]{1,128}`, else no
resume is set. The template is split on spaces into an argv, never run
through a shell. The resume binding is the record's `binding`.

### 2.7 Sanitising agent text

Every string an agent controls (`msg`, OSC 9/777 text, hook payload fields)
passes one function before it is stored:

- C0 and C1 control characters and DEL are removed;
- `#(` becomes `_(` (as `passthrough::safe_title` does) and `#[` becomes
  `##[`, so the text cannot run a command or open a status range in a format;
- it is cut to 200 chars.

Surfaces cut it further by cell width (`unicode-width`).

## 3. Inputs

### 3.1 Recognising agents by program

No timer runs while panes are quiet. A pane is checked:

- when it spawns or respawns;
- on output, at most once per `agents.scan-interval` (default 1 s) per pane,
  from the output wake path (`clients::wake`), as an actor job.

A check reads the foreground leader's argv (`procinfo`) and matches it
against each kind's `match` list:

- the basename of `argv[0]`;
- when `argv[0]` is a launcher (`node`, `bun`, `deno`, `python`, `python3`,
  `uv`, `uvx`, `npx`, `bunx`, `pnpm`), skip it, then skip options and the
  subcommands `run`, `x`, `dlx`, `exec`, and take the next basename;
- never `comm`, which agents set to anything.

A match with no record creates one (state `idle`, unreported, bound to that
process). Dead bindings are swept by `resume.rs`'s sweep, which runs while
any binding (resume or agent) is live and stops when none is.

### 3.2 Reports

All three end in one `agents::report` call.

1. **CLI:** `grofe agent report <state> [-t pane] [--kind k] [--msg text]
   [--blocked permission|question|auth] [--session-id id]`. Default target
   `$GROFE_PANE`. Outside a grofe pane or with no server it does nothing and
   exits 0. It never starts a server (D2).
2. **Hook mode:** `--hook <kind>` adds:
   - it reads the hook payload (JSON, at most 1 MiB) from stdin and takes
     `session_id`; the message is the first string of `message`, `reason`,
     `title`, else `tool_name` plus a short summary of `tool_input` (its
     `command`, `file_path`, `pattern` or `url`, first 60 chars);
   - an unreadable or truncated payload still reports the state, without a
     message;
   - **it exits 0 on everything**, parse errors and unknown flags included:
     a Claude Code `PreToolUse` hook that exits 2 blocks the tool;
   - it is fire and forget: connect with a 30 ms timeout, write the request,
     do not wait for a reply. Hooks run synchronously on every tool call.
3. **OSC 7501** in pane output, parsed by `passthrough::Scanner`:
   `ESC ] 7501 ; pairs ST`, `key=value` pairs joined by `:`. Read `state`
   (required; unknown means ignore), `kind` (to `blocked_kind`), `msg`
   (base64 UTF-8; invalid means no message), `app` (to `kind` when the
   record has none; validated as §2.1). `id` other than the root, `progress`
   and `title` are ignored. `OSC 7501 ; ? ST` is answered with
   `OSC 7501 ; ok ST` to the pane. 7501 is not relayed to the outer
   terminal, and is added to `WRAPPED_OSC` so a `DCS tmux;` wrapped one is
   read too.

### 3.3 Bell and OSC 9/777

On an agent pane that has never reported, a bell or an OSC 9/777
notification sets `unseen` (and, for OSC 9/777, `msg`). It does not change
`state`, so seeing the pane clears it. OSC 9 with a numeric subcommand
(`9;4;...` progress and the other ConEmu `9;N` forms) is ignored. A pane that
has reported ignores both for its record.

## 4. Display

### 4.1 Formats

Pane, window and session variables go in `FormatCtx::get`; server-wide ones
in `ServerVars::get`.

| Variable | Scope | Value |
|---|---|---|
| `agent_kind`, `agent_state`, `agent_msg`, `agent_blocked_kind` | pane | fields; empty when no record |
| `agent_since` | pane | seconds in the current state |
| `agent_unseen`, `agent_attention` | pane | `1` or `0` |
| `window_agent_state`, `session_agent_state` | window, session | rollup, `unseen` shown as `unseen`; empty with no agents |
| `agents_total`, `agents_blocked`, `agents_working`, `agents_attention` | server | counts |
| `notifications_unread` | server | count (§6) |
| `agents_badge` | server | e.g. `⏸2 ✓1`, empty when nothing needs attention |

### 4.2 Default looks (grofe identity only)

- Window status formats gain a glyph from `window_agent_state`: `⏸`
  blocked, `✗` error, `✓` unseen, `●` working. Glyphs are options
  (`agent-glyph-blocked` and so on).
- `status-right`'s default gains
  `#[range=user|agents]#{agents_badge}#[norange]`, and the default
  `MouseDown1Status` binding opens the tray when `mouse_status_range` is
  `agents`.
- A `blocked` agent pane's frame or border uses `agent-blocked-border-style`
  (default `fg=yellow`).
- A state change marks every client dirty, so badges and glyphs update.

## 5. Surfaces

### 5.1 The list widget

One component behind the picker, the tray, the key menu and the sidebar list:
`src/server/listview.rs`, an `Overlay` plus an `InputHook` with per-client
state, like `tree.rs`.

- Rows are rebuilt by the caller on every draw.
- Printable keys type into the query; rows filter by subsequence score,
  ties keep the caller's order.
- Navigation: Up, Down, `C-n`, `C-p`, PageUp, PageDown, Home, End, wheel,
  click. `Enter` runs the row's action. `Escape` or `C-c` closes.
- Each surface adds actions on ctrl keys only, so typing never triggers one.

**Redraws:** a client with a picker open is marked dirty on output from the
selected row's pane; with the grid open, from the panes of the visible
tiles; any agent state change marks every client dirty (§4.2). Times in rows
(`4m`) and toast expiry add their next change to `clients::deadline`.

### 5.2 Picker (`choose-agent`)

Centred overlay, `agents.picker.width` by `height` (default 80% by 70%).
Rows sorted by urgency, then oldest `since` first:

```
⏸ blocked   4m   work:2.1   claude   permission: Bash rm -rf build   ~/work/api
● working   0:38 grofe:2.1  claude   Edit src/server/model.rs        ~/p/grofe
○ idle      12m  notes:1.1  pi                                       ~/notes
```

State, time in state, `session:window.pane`, kind, message, cwd. The selected
pane is previewed live below the list. Actions: `Enter` jump, `C-x` kill the
pane (asks first), `C-y` copy the target to the clipboard (OSC 52), `C-s`
mark seen.

**Jump** (picker, sidebar, grid, tray, `agent next`): the jumping client is
the one that ran the command; from a CLI outside any client, the most
recently active client. If that client's current session contains the pane's
window (linked windows included), it stays in its session; else it switches
to the pane's session. Then the window and pane are selected. A hidden
scratchpad (once `feat/scratchpads` has merged) is shown first.

### 5.3 Sidebar (`agent-sidebar on|off|toggle|focus`)

A strip of `agents.sidebar.width` columns (default 32) plus a one-cell
separator at the right of a client's view, per client, hidden at attach
unless `agents.sidebar.show-on-attach`.

- Drawn by the server: not a pane, no process, no hooks.
- Rows: agents grouped by session, two lines each (glyph, `window.pane`,
  kind; then the message). Redrawn on state changes, not on pane output.
- Geometry: it reserves columns as the status line reserves rows.
  `window_size` gains the owner client, passed from `apply_sizes`; the window
  shrinks by `width + 1` when the size-owning client (D6) has its sidebar
  shown. Toggling it therefore resizes the window and every pane in it gets
  SIGWINCH. Other clients on that window are cropped as for any smaller
  client (D6).
- Hidden while the client is narrower than `min-client-width` (default 120).
- Click a row to jump. `agent-sidebar focus` routes keys to it (list widget
  keys); `Escape` gives them back.

### 5.4 Grid (`agent-grid`)

A full-view overlay of tiles, one per agent pane, in as many columns as fit
`agents.grid.tile-width` (default 60). Tile: a title (glyph,
`session:window.pane`, kind, time in state) and the bottom
`agents.grid.preview-lines` (default 12) rows of the pane, cropped. Read
only. Arrows move, `Enter` jumps, typing filters, `Escape` closes; overflow
scrolls by row.

### 5.5 Key menu (`key-menu [-T table]`)

Replaces tmux-which-key. Under grofe identity `prefix Space` runs
`key-menu -T prefix`, and `next-layout` moves to `prefix M-Space`. Under tmux
identity the stock table is untouched.

- Lists the table's bindings by `group`, each with its key and description
  (`bind -N` note or TOML `desc`). Bindings with no group go to `other`.
  Mouse keys and the `Any` binding are not listed.
- **A key bound in the table runs its binding at once** and closes the menu,
  as which-key does; a `-r` binding leaves the client in the prefix table as
  a normal press would.
- The menu reserves `C-n`, `C-p`, `C-f`, `Escape` and `C-c`, which win over
  the table: `C-n` and `C-p` move, `C-f` starts filtering (the list widget's
  query; then `Enter` runs the selected row). A binding on a reserved key is
  still listed and reachable by filtering.
- A binding whose command is `switch-client -T <t>` is a submenu: it opens
  `<t>`'s menu.
- Group names and descriptions are formats, so `Agents
  (#{agents_attention})` works.
- Bindings get a group: the parsed TOML `group` is kept on `Binding`,
  `bind-key -G <group>` sets it, `list-keys -N` shows it, and grofe's
  default bindings get groups (pane, window, session, copy, layout, agents,
  notifications, client, other).

## 6. Notifications

### 6.1 Raising

On an agent's transition into a state in `notify.on` (default `blocked`,
`error`, `done`):

- not when the pane is seen and `notify.skip-when-seen` (default on);
- `done` only after at least `notify.done-min-work` (default 30 s) of
  `working`;
- at most one per pane per `notify.min-interval` (default 10 s); a later one
  inside it replaces the earlier one's text.

### 6.2 Tray

A notification is: id, pane uid, kind, state, message, time, read. The tray
keeps the newest `notify.history` (default 10).

- It becomes **read** when its pane is seen, or when the agent leaves the
  state it was raised for.
- `choose-notification` opens it in the list widget: `Enter` jumps, `C-x`
  dismisses one (mouse: the `x` at the row's end), `C-l` clears all.
- CLI: `notify list`, `notify dismiss <id>`, `notify clear`.

### 6.3 Toasts

The newest unread notification is drawn as a box in the top-right corner of a
client's view for `notify.toast-time` (default 5 s), on clients not looking
at the pane. Click jumps; its `x` dismisses. A newer one replaces it.
`notify.toast` lists the states that toast (default `blocked`).

### 6.4 Desktop

`notify.desktop` lists the states that leave the terminal (default
`blocked`, `error`, `done`). Only configured kinds raise desktop
notifications, so `cat`ing a file with OSC 7501 cannot. `notify.delivery`:

- `auto` (default): `terminal` when some attached client's terminal is
  known to be unfocused; `command` when no client is attached; else nothing.
- `terminal`: OSC 9 (`ESC ] 9 ; text ST`) to every attached client. Ghostty,
  WezTerm, iTerm2 and kitty show it as a desktop notification on macOS and
  Linux, also over ssh.
- `command`: an argv, never a shell string, run off the actor with a 10 s
  timeout, one in flight (later ones coalesce into the next run). Built in:
  - Linux: `notify-send -a grofe -- <title> <message>`;
  - macOS: `osascript -e 'on run argv' -e 'display notification (item 2 of
    argv) with title (item 1 of argv)' -e 'end run' -- <title> <message>`
    (agent text arrives as data, never as script source);
  - `notify.command` overrides it: an argv array with `{title}`,
    `{message}`, `{pane}`, each substituted into a single element; the docs
    say a template must put `--` before agent text.
- `off`.

`notify.sound` (default off) adds a sound: `sound name "default"` in the
osascript script, `-h string:sound-name:message-new-instant` for
notify-send.

While desktop delivery is on, OSC 9/777 from agent panes that have reported
is not relayed to clients, so the user is not notified twice.

### 6.5 Off switches

- `notify.enabled = false`: nothing is raised.
- Per channel: `notify.toast = []`, `notify.desktop = []`.
- `notify mute [duration]` and `notify unmute`: notifications go to the tray
  only; the badge shows `notify-muted-glyph` (default `🔕`).

## 7. Starting agents (`agent new`)

`agent new <kind> [-p] [-c dir] [-n name] [-w | -W] [-b branch] [-d]`:

- opens a window (`-p`: a split of the current pane) in `dir` (default the
  current pane's path) running the kind's `command`, and creates its record
  (state `idle`);
- `-w` uses a new worktree, `-W` never; otherwise the kind's or
  `agents.new.worktree` (`ask`, `always`, `never`; default `never`) decides;
  `ask` prompts for a branch, empty meaning none;
- the worktree comes from `agents.new.worktree-command`, an argv with
  `{dir}`, `{branch}` and `{path}`. Default:
  `["git", "-C", "{dir}", "worktree", "add", "-b", "{branch}", "{path}"]`,
  `{path}` being `<repo root>/../worktrees/<branch, / as ->`. When the
  command's last stdout line is an existing directory, that is the worktree;
  else `{path}`. A failure shows its stderr as a message and opens nothing.
- Branch names: no whitespace, no `..`, no leading `-`, no control
  characters, at most 100 chars.

## 8. Integrations (`agent setup`)

`grofe agent setup <kind> [--dry-run] [--remove] [--yes]`, run by the CLI,
no server needed:

- Shows the change and asks unless `--yes`.
- Edits the resolved file in place (a symlinked, dotfile-managed file stays a
  symlink), after a one-time backup `<file>.grofe-bak`.
- JSON is edited with key order preserved (`serde_json`'s `preserve_order`
  feature, added to `Cargo.toml` by the task that owns it).
- Its entries are the hook commands that start with grofe's absolute path
  followed by `agent report`; `--remove` takes exactly those out, and a second
  run changes nothing.
- Commands use the absolute path of the running binary, so agents started
  without grofe on PATH (IDE launches) still find it.
- `agent setup --status`: per kind, installed, not installed, or agent not
  found.

**claude:** merges into `$CLAUDE_CONFIG_DIR/settings.json`, else
`Claude Code's settings.json`: `SessionStart` idle; `UserPromptSubmit`,
`PreToolUse`, `PostToolUse` working; `Notification` matcher
`permission_prompt` blocked (`--blocked permission`), `idle_prompt` done;
`Stop` done; `SessionEnd` exited. Each command is `<grofe> agent report
<state> --hook claude`.

**codex, opencode, pi, gemini:** each hook or plugin format is checked
against the agent's current documentation when its task starts and recorded
in that task; a kind without a hook mechanism ships `match` and `resume`
only and relies on §3.3.

| Kind | `match` | `resume` |
|---|---|---|
| `claude` | `claude` | `claude --resume {id}` |
| `codex` | `codex` | `codex resume {id}` |
| `opencode` | `opencode` | `opencode --session {id}` |
| `pi` | `pi` | checked at implementation |
| `gemini` | `gemini` | none |
| `aider` | `aider` | none |

A resume template that cannot be checked ships empty.

## 10. Commands, events, compat

| Command | Purpose |
|---|---|
| `agent report <state> ...` | §3.2 |
| `agent list [-F format]` | one line per agent pane, urgency order |
| `agent next` | jump to the most urgent attention pane, oldest first within a level; "no agent needs you" otherwise |
| `agent seen [-t pane]`, `agent seen -a` | mark seen |
| `agent new <kind> ...` | §7 |
| `agent setup <kind> ...` | §8 |
| `choose-agent`, `agent-sidebar ...`, `agent-grid` | §5 |
| `key-menu [-T table]` | §5.5 |
| `choose-notification`, `notify list\|dismiss\|clear\|mute\|unmute` | §6 |

- **Event `agent-changed`** enters the catalog (design spec §7.2, additive):
  pane, uid, kind, old state (null for a new record), new state. Named
  consumer: this spec's integration tests (§13), which subscribe to it. A
  `set-hook` name of the same spelling is accepted.
- **Compat:** none of these exist in tmux; under the tmux front end they are
  unknown verbs. the session manager calls them as `grofe`.

## 11. the session manager changes (separate repository)

After steps 2, 3, 4 and 6 (§12):

- Remove opensessions, tmux-claude-session-manager and tmux-which-key from
  the loader list in `grofe/templates/30-private-plugins.toml` and from the
  vendored plugins; drop the `bind-key C-s send-prefix` re-assert and the
  which-key options.
- Under grofe, `adapters/claude-code/report.sh` and `private-agent report`
  call `grofe agent report ... --hook claude`, and `the session manager agent install`
  calls `grofe agent setup`. The tmux path is unchanged.
- Generated grofe keys carry keys.tsv's group, so the key menu shows the session manager's
  groups.
- The status segment uses `#{agents_badge}` instead of the session manager's own count.
- The owner's `user.toml` drops `claude_launch_key` and `claude_list_key`.

## 12. Build order

1. **Core:** records, transitions, ordering, binding and sweep, seen,

   `[agents]` config, built-in kinds, **`agent setup claude`**, key `u`.

3. **Notifications:** tray, toasts, badge and its click, desktop, `[notify]`;

5. **Grid**; key `O`.
6. **`agent new`** with worktrees; **`agent setup`** for the other kinds.
7. **the session manager** (§11).
